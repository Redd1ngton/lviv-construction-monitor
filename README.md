# Монітор нової забудови Львівської області (e-construction.gov.ua)

Парсер + веб-інтерфейс для автоматичного збору інформації про об’єкти, які починають будувати в **Львівській області**.

### Що вміє
- Збирає дані з реєстру дозвільних документів (optype=100) з фільтром по Львівській області.
- Може брати дані за довший період, ніж 30 днів (через фільтр «Дата реєстрації»), щоб не втрачати об’єкти.
- Систематизує: номер документа, дата, назва/тип об’єкта, адреса, замовник, статус, посилання на картку.
- Зберігає результат у `data/constructions.json` та `data/constructions.csv` (можна завантажити на ПК).
- Підтримує сортування за будь-яким полем.
- Має простий інтерфейс з таблицею + картою (Leaflet) + побудовою маршруту між обраними точками (найближчий сусід + можливість експорту в Google Maps).

## Як це працює

1. **Парсер** (`parser/scrape.py`) відкриває сторінку реєстру через Playwright (реальний браузер).
2. Застосовує фільтри:
   - Область = Львівська
   - (опційно) діапазон дат реєстрації — щоб брати не тільки останні 30 днів
   - Статус = Діючий (за замовчуванням)
3. Проходить по сторінках результатів, збирає список документів.
4. Для кожного документа відкриває детальну картку і витягує додаткові поля (назва об’єкта, адреса, замовник тощо).
5. Якщо на картці/карті є координати — зберігає їх.
6. Зберігає структурований JSON + CSV у папку `data/`.
7. **Frontend** читає JSON і показує:
   - Фільтровану/сортовану таблицю
   - Точки на карті
   - Можливість обрати кілька об’єктів і прокласти приблизний оптимальний маршрут (алгоритм nearest-neighbor) + посилання на Google Maps з кількома точками.

> **Важливо**: сайт e-construction.gov.ua — динамічний (Vue + Element UI). Парсер може потребувати невеликих правок, якщо зміниться структура сторінки. Запускайте з паузами, щоб не перевантажувати сервер.

## Встановлення і запуск парсера (на своєму ПК)

### Вимоги
- Python 3.10+
- Playwright

```bash
cd parser
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
playwright install chromium
```

### Запуск
```bash
# Зібрати дані за останні 90 днів (можна змінити в коді)
python scrape.py --days 90 --max-pages 20

# Або за конкретний період
python scrape.py --from-date 2026-07-01 --to-date 2026-10-22
```

Результат з’явиться в `../data/constructions.json` та `.csv`.

Файл можна просто завантажити на ПК і відкрити в Excel / Google Sheets.

## Деплой на Cloudflare

### Варіант 1 — Cloudflare Pages (найпростіший)
1. Зайди на [Cloudflare Dashboard](https://dash.cloudflare.com) → Pages → Create project → Connect to Git.
2. Вибери цей репозиторій.
3. Build settings:
   - Framework preset: None
   - Build command: (залиш порожнім)
   - Build output directory: `frontend`
4. Deploy.
5. Після деплою сайт буде роздавати `index.html` + `app.js`.  
   JSON лежить у `data/` — щоб frontend його бачив, або:
   - Скопіюй `data/constructions.json` у `frontend/data.json` перед деплоєм,
   - Або налаштуй Cloudflare R2 + public bucket і змінюй URL у `app.js`.

### Варіант 2 — Дані окремо в R2
1. Створи R2 bucket.
2. Завантажуй туди `constructions.json` після кожного запуску парсера.
3. Зроби bucket публічним або через custom domain.
4. У `frontend/app.js` зміни `DATA_URL` на посилання на R2.

### Варіант 3 — GitHub Actions + Pages
У `.github/workflows/` можна налаштувати щоденний запуск парсера (потрібен self-hosted runner або Actions з Playwright — трохи складніше, бо потрібен браузер). Для початку краще запускати парсер локально або на VPS/Railway/Render і пушити тільки оновлений JSON.

## Як користуватися інтерфейсом

1. Відкрий сайт (локально або на Cloudflare).
2. Таблиця показує всі зібрані об’єкти.
3. Сортування — клік по заголовку колонки.
4. Фільтр по тексту — поле пошуку.
5. На карті — маркери.
6. Відміть чекбоксами кілька об’єктів → кнопка «Побудувати маршрут».
7. Отримаєш приблизний порядок об’їзду + пряме посилання на Google Maps з точками.

## Подальші кроки (рекомендації)

1. Запусти парсер локально один раз і перевір, чи всі потрібні поля витягуються.
2. Якщо сайт змінив селектори — напиши мені, підправимо.
3. Налаштуй Cloudflare Pages (5–10 хвилин).
4. (Опційно) Зроби простий cron / GitHub Action / Railway cron, щоб раз на день оновлювати JSON.
5. Якщо потрібні сповіщення в Telegram про нові об’єкти — можна додати.

## Обмеження і відповідальність

- Дані беруться з публічного реєстру ЄДЕССБ. Використовуй відповідально.
- Не запускай парсер занадто часто (рекомендовано 1 раз на день).
- Координати є не завжди — тоді маршрут будується тільки по тих точках, де вони є.
- Алгоритм маршруту — простий (nearest neighbor). Для точного оптимуму можна підключити OSRM або Google Directions API (платно при великому обсязі).
