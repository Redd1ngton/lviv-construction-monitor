# Агрегатор будівництв України

Автоматичний збір публічних дозвільних документів [ЄДЕССБ](https://e-construction.gov.ua/document/optype=100), фільтри, карта, спільний маршрут та порівняння знімків.

## Щоденний збір і області

GitHub Actions запускає `.github/workflows/daily-scrape.yml` щодня о **04:17 UTC** лише для регіонів у `parser/collection.json` (за замовчуванням — Львівська область). Підтримуються 24 області, АР Крим, Київ і Севастополь; доступність результатів залежить від відкритого реєстру. Кожен регіон має окреме завдання; одночасно працюють не більше двох. Успішні регіони публікуються навіть якщо інші завершилися помилкою. До завершення першого замовленого збору дані нової області можуть бути відсутні. Зміна прапорців фільтрує поточні результати; новий збір запускає кнопка «Почати збір обраних регіонів» після підключення серверного обробника нижче.

Період за замовчуванням — **7 днів** з накопиченням попередніх спостережень. Це не повна історична копія реєстру. Для ручного збору: **Actions → Update construction registry → Run workflow**, вставте `regions` (наприклад `lviv,odesa`) та `days` (1–90). Чекбокси на сайті формують список регіонів і зберігають вибір у браузері; кнопка запуску надсилає обрані коди серверу Cloudflare. Ручний варіант GitHub з копіюванням кодів залишається резервним. Перед запуском усіх регіонів сайт просить підтвердження, а workflow додатково вимагає `confirm_country=true` для кожного ручного запуску. Автоматичний збір усієї країни заборонено навіть якщо всі коди внесені у конфігурацію. Коди й назви — `parser/regions.py`. Для розкладу й ручного запуску з GitHub додатковий сервер не потрібний: workflow використовує вбудований `GITHUB_TOKEN` із правом запису в репозиторій. GitHub може затримувати розклад або призупиняти його після тривалої неактивності публічного репозиторію.

Парсер застосовує фільтр області й перевіряє адресу, дату та статус кожної картки. Неповний збір, повторена сторінка або невпізнаний HTML не публікуються. Підтверджений реєстром нуль результатів не видаляє стару історію. Статуси старих записів відображають стан на момент останнього спостереження; вони не перевіряються щодня поза вікном збору. Документи можуть стосуватися як початку робіт, так і введення в експлуатацію.

## Робота з об’єктами

- Вкладки типів об’єкта, фільтри області, населеного пункту, документа, дат і координат.
- Тип об’єкта визначається евристично за назвою; його слід перевіряти за повним описом.
- Вибір до 10 об’єктів **зберігається між вкладками та фільтрами**. Обрані зупинки видно у спільному списку; кожну можна прибрати окремо. Зміна набору даних прибирає обрані записи, яких у ньому вже немає.
- Кнопка «Додати видимі до маршруту» доповнює поточний вибір до ліміту. Кнопка маршруту активується після вибору щонайменше двох точок.
- На карті пунктир показує порядок відвідування та відстань по прямій. Автомобільний маршрут відкривається в Google Maps. Мобільний Google Maps може обмежувати кількість проміжних зупинок.

## Знімки та порівняння

«Зберегти поточний збір у JSON» зберігає копію у пам’яті браузера (IndexedDB) та завантажує файл на пристрій. Через тиждень цей JSON можна імпортувати знову. Можна завантажити **кілька файлів одночасно**, обрати потрібні знімки прапорцями й показати:

- поточний парсер;
- усі обрані результати разом;
- лише нові номери документів відносно обраного попереднього знімка;
- лише записи зі зміненими основними полями.

Для порівняння оберіть базовий знімок. Перемикач дозволяє додати до порівняння актуальні дані парсера. Повторні номери прибираються; за однаковим номером переважає версія з новішою датою збору. «Нові» означає відсутні у базовому знімку, а не обов’язково новозареєстровані. Без дати збору версії вважаються найстарішими. Імпорт обмежений 20 МБ на файл і 50 000 записів.

Пам’ять браузера не синхронізується між пристроями та може бути очищена. Зберігайте JSON-файли для надійного перенесення. При недоступній IndexedDB файли все одно можна завантажити й порівнювати в поточному сеансі.

## Координати

Парсер читає явні мітки та кадастрові номери. Для однієї ділянки запитує `/api-user/gis-url-proxy?cadparcel=...` — джерело карти ЄДЕССБ. Успішні координати кешуються. Центр ділянки не гарантує позицію будівлі; кілька ділянок не перетворюються на одну довільну точку. Після трьох збоїв за запуск нові кадастрові запити припиняються до наступного збору. На перевірці 23.10.2026 сервіс повертав HTML-сторінку таймауту. Однаковий `cc` у посиланнях різних карток не використовується як координата об’єкта.

Резервні **приблизні центри населених пунктів** беруться з локальних регіональних довідників [GeoNames](https://www.geonames.org/) (CC BY 4.0, без гарантії точності). Вони позначені помаранчевим. Координати реєстру та ручні точки — синім. Однакові точки об’єднані у мітку з кількістю записів. Неоднозначним назвам точка не призначається.

«Уточнити точку» дозволяє натиснути місце на карті або ввести координати. Ручні точки зберігаються лише в цьому браузері у `localStorage`; JSON-знімки містять дані парсера, а не ці приватні виправлення. «Скинути точку» повертає джерельне розташування.

## Стан збору

Панель показує етапи GitHub Actions, сторінку, оброблені й підтверджені записи та час активності. Знімки прогресу публікуються в окремій гілці `parser-status` як `status-<region>.json`, що не перебудовує сайт. Перевірка прогресу — кожні 20 секунд, етапів Actions — кожні 3 хвилини; є ручне оновлення. Після 5 хвилин без активності показується попередження. Вибір області змінює показаний регіональний статус.

## Cloudflare Pages

Framework: None; build command: порожньо; output directory: `frontend`.

Сайт запитує `data/constructions.json` із `main`, з локальним резервним `frontend/data.json`. Після зміни інтерфейсу потрібен звичайний деплой Cloudflare. Версії скриптів у HTML запобігають змішуванню старих і нових модулів у кеші.

## Локально

```bash
pip install -r parser/requirements.txt
python parser/scrape.py --region lviv --days 7
python parser/scrape.py --region odesa --days 7 --output-dir /tmp/odesa-scrape
python -m unittest discover -s tests -v
node tests/frontend.cjs
node tests/datasets.cjs
python -m http.server 8000
```

Відкрийте http://localhost:8000/frontend/ . `--output-dir` дозволяє відокремити пробний збір від основного набору. Історія регіонів — `data/regions/`, спільний набір — `data/constructions.json` і CSV, кеші кадастру — `data/coordinate-caches/`. `scripts/merge_regions.py` об’єднує успішні регіональні артефакти, зберігаючи попередню історію інших областей. Довідники населених пунктів відтворюються `python scripts/build_places.py` з офіційного GeoNames `UA.zip`.

## Примусове оновлення та адреси

Кнопка «Примусово оновити дані» повторно завантажує останній опублікований набір з параметром обходу кешу, зберігає обрані області та повідомляє дату збору. Вона не запускає нове сканування реєстру: для нього використовуйте запуск обраних регіонів через GitHub. При зміні області скидається старий населений пункт; кнопки «Лише ця» швидко залишають один регіон.

Парсер зберігає `street_address`, `house_number`, `full_address` із блоку адреси/опису місцезнаходження об’єкта. Після явної геометрії та координат ділянки доступний резервний пошук за вулицею через той самий `/api-user/gis-url-proxy?searchtext=...`, який використовує карта реєстру. Результат приймається тільки при збігу населеного пункту, назви вулиці та вказаного номера будинку. Центр вулиці без номера позначається приблизним (`registry_street`), адресний результат з номером — `registry_address`; це результат пошуку, який слід перевірити перед виїздом. Успіхи кешуються, після трьох невдалих адресних запитів за запуск нові припиняються. Недоступність сервісу не перетворює адресу на вигадану точку.

У Google Maps для приблизної точки з відомою вулицею передається повна адреса замість центру населеного пункту. Дані адресного сервісу перевіряються незалежно від працездатності самої карти.


## Кнопка оновлення та живий статус

Кнопка «Оновити дані» розташована безпосередньо у панелі парсера. Вона повторно завантажує опубліковані результати без кешу та запитує стан запуску. Прогрес перевіряється кожні 10 секунд, лічильник часу оновлюється щосекунди; знімки активності публікуються парсером кожні 30 секунд. Етапи GitHub запитуються рідше, щоб дотримуватися ліміту публічного API. Збір карток і публікація відображаються окремо: успішний збір області не видається за завершену публікацію. Після успішної публікації дані автоматично підвантажуються один раз на запуск без скидання режиму порівняння знімків; при мережевому збої спроба повторюється. Кнопка завантажує готові дані; запуск нового збору виконується через існуючий запуск обраних регіонів у GitHub.

## Відновлення після порожнього фільтра та повторів кінцевої сторінки

Активні області, пошук і додаткові фільтри показуються окремим видимим рядком. Якщо області не обрані або для них немає даних, повідомлення прямо пояснює причину. «Скинути всі фільтри» очищає також пошук і відновлює Львівську область (або першу область із наявних даних), без запуску парсингу. При порожній таблиці доступна додаткова кнопка скидання.

Реєстр може повторити вже перевірені картки на останній сторінці. Відсутність посилання Next дозволяє завершити та зберегти унікальні записи; повторення тієї самої проміжної сторінки з Next залишається помилкою. Завершена помилка GitHub має пріоритет над старим знімком активності: етап збору не показується активним після зупинки, а лічильники позначені як останній відомий прогрес.


## Справжній запуск збору з сайту (Cloudflare Pages Functions)

Статичний браузерний фільтр сам не запускає GitHub Actions. `functions/api/parser.js` додає серверний `POST /api/parser`, який перевіряє ключ керування, список регіонів, період і підтвердження всієї країни та викликає workflow dispatch. Сайт показує прийняття запиту тільки після успішної відповіді GitHub і відстежує повернутий ідентифікатор запуску; за старішої відповіді 204 знаходить запуск за UUID у назві. Переходити в GitHub і копіювати коди для звичайного запуску більше не потрібно.

### Одноразове підключення власником

1. Використовуйте **Cloudflare Pages** із Git-репозиторієм. Root directory — корінь репозиторію; build output directory — `frontend`. Каталог `functions/` має залишатися у корені репозиторію. У `frontend/_routes.json` виклики `/api/*` спрямовані у Functions.
2. Створіть fine-grained GitHub token лише для `Redd1ngton/lviv-construction-monitor` з дозволом **Actions: read and write**. Цей токен потрібний серверу сайту; вбудований токен workflow не доступний Cloudflare.
3. Cloudflare → Workers & Pages → ваш Pages-проєкт → Settings → Variables and Secrets → Production: додайте **секрети** `GITHUB_TOKEN` і `PARSER_ADMIN_KEY`. Другий — окремий випадковий ключ керування, рекомендовано від 32 символів. Не додавайте їх у репозиторій, JSON-файли, URL чи чат.
4. Виконайте повторне розгортання Pages. На сайті має з’явитися «Запуск із сайту підключено». Введіть `PARSER_ADMIN_KEY` у поле «Ключ керування»; GitHub token у браузер не вводиться.
5. Відмітьте області, задайте період і натисніть «Почати збір обраних регіонів». Ключ керування залишається лише у полі поточної сторінки, без localStorage/sessionStorage. Ідентифікатор запуску (без ключа) зберігається у sessionStorage для відстеження після перезавантаження.

Якщо секрети або Functions не налаштовані, інтерфейс прямо повідомляє, що запуск не відбувся. Backend повертає 401 для неправильного ключа, 400 для некоректного списку/періоду або непідтвердженої всієї країни, 409 при вже зайнятій черзі та 502 при відмові GitHub. Картки починають з’являтися після реального завершення збору та публікації; прийняття запиту не означає завершення. Усі регіони без підтвердження не запускаються.

Зміни коду тепер запускають окремий workflow `Validate application` з тестами. Новий збір більше не запускається через кожну зміну JavaScript чи парсера: він стартує за розкладом, ручним запитом або зміною `parser/collection.json`. Проміжні повторені сторінки реєстру повторно запитуються без кешу; лише три послідовні сторінки без нового прогресу зупиняють збір.

Тести серверного маршруту: `node tests/parser-api.mjs`; усі вони використовують підставний GitHub, не запускаючи реальний збір і не вимагаючи секретів.
