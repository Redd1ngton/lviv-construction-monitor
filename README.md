# Монітор забудови Львівської області

Автономний збір публічних дозвільних документів ЄДЕССБ та статичний сайт: пошук, сортування, карта й маршрут між об'єктами з координатами.

## Автоматичне оновлення

`.github/workflows/daily-scrape.yml` запускає збір щодня о **04:17 UTC** (06:17 взимку / 07:17 влітку за Києвом), а також після змін парсера в `main`. Час запуску GitHub Actions може затримуватися. Ручний запуск: **Actions → Update construction registry → Run workflow**.

Потрібні увімкнені GitHub Actions і дозвіл workflow на запис у репозиторій. Використовується вбудований `GITHUB_TOKEN`, окремі токени, сервер та Playwright не потрібні. Організаційні обмеження можуть заборонити запис; у такому разі помилка буде в журналі Actions. GitHub може призупиняти розклад у публічних репозиторіях після тривалої відсутності активності — перевіряйте Actions, якщо дата даних застаріла.

Кожен запуск:

1. Збирає документи за останні 30 днів через серверні фільтри реєстру.
2. Проходить усі сторінки, відкриває кожну картку і додатково перевіряє адресу Львівської області, дату та статус «Діючий».
3. Об'єднує записи за номером документа, зберігаючи попередню історію.
4. Записує JSON і CSV, копіює їх у `frontend/` та комітить результат.

Помилки HTTP повторюються з паузами. Невпізнана сторінка, повторена пагінація, перевищення ліміту сторінок або відсутність перевірених записів завершують запуск помилкою **без публікації часткових результатів**. Помилка видима в Actions; попередні дані залишаються доступними. Відсутність результатів також вважається приводом перевірити джерело, а не видаляти архів.

## Дані та межі

Джерело: https://e-construction.gov.ua/document/optype=100 . Коди фільтрів і CSS-структура перевірені на реєстрі 23.10.2026. Використовується звичайний HTTP та HTML, без неофіційного закритого API.

Поля: номер, дата реєстрації, назва, адреса, замовник (лише оприлюднені відомості), тип документа, статус, орган видачі, посилання на картку. Реєстр містить і початок робіт, і введення в експлуатацію, тому запис не обов'язково означає нове будівництво. Тип документа доступний у таблиці й пошуку.

Це **архів спостережень**, а не повна актуальна копія реєстру: перевіряються картки в поточному 30-денному вікні, давніші записи зберігаються зі статусом на момент останнього збору. Для ширшого початкового охоплення запустіть збір з `--days 90` чи конкретними датами. Координати не вгадуються: поки джерело не надає їх у підтримуваному структурованому вигляді, `lat/lon` залишаються порожніми, маршрут недоступний для таких записів.

## Cloudflare Pages

- Framework: None
- Build command: порожньо
- Build output directory: `frontend`

Після успішного Actions файли `frontend/data.json` та `frontend/data.csv` готові до публікації. Сайт спочатку запитує актуальний JSON із `main` через GitHub Raw, потім пробує локальні файли. Тому оновлення даних не залежить від запуску нового Cloudflare build. Перший збір може зайняти тривалий час; до його завершення таблиця може бути порожня.

## Локальний запуск

Python 3.10+:

```bash
pip install -r parser/requirements.txt
python parser/scrape.py --days 30
python parser/scrape.py --from-date 2026-10-01 --to-date 2026-10-22
python -m unittest discover -s tests -v
python -m http.server 8000
```

Відкрийте http://localhost:8000/frontend/ . Параметри `--max-pages` (1000), `--delay` (1.2 секунди між запитами) і `--output-dir` дозволяють обмежувати навантаження та відокремлювати пробні результати. Досягнення ліміту сторінок завершується помилкою: неповний збір не видається за успішний.

JSON: `data/constructions.json`; CSV для Excel: `data/constructions.csv` (UTF-8 BOM). Текстові значення CSV захищені від виконання формул. Посилання з реєстру в інтерфейсі обмежені HTTPS-доменом джерела. Якщо Leaflet не завантажився, таблиця продовжує працювати.

## Стан парсингу на сайті

Панель «Збір даних» показує етапи GitHub Actions, стан останнього запуску та посилання на його журнал. Під час збору додаються номер сторінки, кількість оброблених карток, приблизна загальна кількість і кількість підтверджених записів. Знімок активності публікується щохвилини в окремій гілці `parser-status` (`status.json`), що не запускає перебудову сайту. Сайт перевіряє цей знімок кожні 20 секунд, етапи Actions — кожні 3 хвилини; кнопка дозволяє перевірити одразу.

Якщо понад 5 хвилин немає нового знімка активного збору, з'являється попередження. Відсутність доступу до статусу не означає зупинку парсера: сайт показує час останньої активності та пропонує журнал. Для запусків попередньої версії доступні етапи без лічильників. Окремі токени у браузері не використовуються.


## Фільтри, карта і маршрут

Додано окремі фільтри населеного пункту, категорії об’єкта (за назвою), типу документа, дат та наявності координат. Категорія — автоматична евристика, її слід перевіряти за назвою. Усі фільтри спільні для таблиці й карти. Чекбоксами або кнопками у мітці можна обрати до 10 об’єктів для порядку об’їзду й передати точки в Google Maps для автомобільної навігації. На нашій карті пунктир — порядок відвідування та відстань по прямій, а не дорожня траса. При зміні фільтра приховані об’єкти прибираються з вибору.

Парсер шукає явні координати мітки в HTML картки та кадастрові номери. Для однієї ділянки використовує той самий публічний запит, що карта ЄДЕССБ: `/api-user/gis-url-proxy?cadparcel=...`. Координати кешуються у `data/parcel_coordinates.json`; центр ділянки має джерело `registry_parcel` і не є гарантованою позицією самої будівлі. Кілька ділянок не зводяться до однієї довільної точки. Після трьох збоїв джерела за запуск нові кадастрові запити призупиняються до наступного збору. На перевірці 23.10.2026 цей сервіс двічі повернув HTML-сторінку таймауту замість координат. Параметр `cc` у кадастрових посиланнях перевірених різних карток однаковий, тому як координата об’єкта не використовується.

Як резерв використовуються **приблизні центри населених пунктів** з локального довідника [GeoNames](https://www.geonames.org/) (CC BY 4.0, дані без гарантії точності). Довідник сформовано `scripts/build_places.py` з офіційного `UA.zip`. Неоднозначні назви в одному районі не отримують випадкової точки. Помаранчеві мітки — приблизні, сині — координати реєстру/ділянки або уточнені вручну. При збігу координат мітка містить кількість записів та список об’єктів.

Кнопка «Уточнити точку» дозволяє натиснути місце на карті або ввести широту/довготу. Такі виправлення зберігаються лише в поточному браузері (`localStorage`), не змінюють реєстр та доступні після перезавантаження. «Скинути точку» повертає координати джерела. Якщо довідник не містить однозначного місця, запис залишається у таблиці з можливістю встановити точку вручну.

Перевірки: `python -m unittest discover -s tests -v` і `node tests/frontend.cjs`.
